# Prepare for an interview

## Inputs

- Job description text (required).
- Resume text or file (strongly preferred; needed for STAR drafts).
- Optional: interview stage (recruiter screen, hiring manager, technical,
  panel, final), company name, interviewer title, time available.

If the job description is missing, ask for it and stop. If the resume is
missing, produce the question bank and ask for the resume to draft answers.
Ask at most one question.

## Procedure

1. **Identify what the interview will probe.** From the job description,
   list the top responsibilities, required skills, and any signals about
   stage or culture. Note the stage if the user gave one.
2. **Build the question bank** using `references/question-bank.md`.
   Produce 10–15 questions grouped as: role-specific, behavioral, situational
   or case, and logistics/motivation. Tie each role-specific question to a
   line in the job description.
3. **Draft STAR answers** for the 3–5 most likely questions using evidence
   from the resume. Each: Situation (1 line), Task (1 line), Action (2–3
   lines), Result (1 line with the user's real number or a `[add metric]`
   placeholder). Mark where the user must fill in detail the resume lacks.
4. **List gaps.** Requirements the resume does not cover, with one honest
   framing the user could use (transferable experience, learning plan) —
   never a fabricated story.
5. **Suggest 4–5 questions for the interviewer**, specific to the job
   description, not generic.
6. **Deliver** in that order. If the user asked for a mock interview, ask one
   question at a time and give brief feedback after each answer instead.

## Never do

- Never invent experiences or outcomes for STAR answers.
- Never claim knowledge of the company's actual interview process; present
  questions as likely, not confirmed.
- Never browse for company information; use what the user provides.

## Hand-off

Offer a mock-interview round or `offer-negotiation` prep. Explicit user
instructions override this skill.
